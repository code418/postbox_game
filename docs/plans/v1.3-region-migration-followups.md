# v1.3 region migration — operational follow-ups

The Firebase region migration (us-central1 → europe-west2 / Firestore nam5 →
eur3) is **code-complete and deployed**: all Cloud Functions are region-pinned
(`europe-west2`, with `onFriendAdded` on `europe-west4` for the eur3 Eventarc
mapping), the Flutter client routes through `lib/firebase_functions_eu.dart`, and
the `functions/pre-nam5.json` / `functions/post-eur3.json` snapshots match.

Two steps remain. **Both are gcloud/console operations, not code** — do them when
ready; nothing in the app depends on them shipping together with the v1.3
observability work.

## 1. EU Storage bucket (optional, low priority)

The live default bucket is **`the-postbox-game.appspot.com`** (US multi-region).
Storage round-trips matter far less than Firestore's, so this can stay deferred.
If/when you migrate it:

```bash
# Buckets can't be relocated — create a new EU one.
gsutil mb -l europe-west2 gs://the-postbox-game-eu

# Copy the existing objects (report photos + generated OSM changesets).
gsutil -m cp -r gs://the-postbox-game.appspot.com/report_photos   gs://the-postbox-game-eu/
gsutil -m cp -r gs://the-postbox-game.appspot.com/osm_changesets  gs://the-postbox-game-eu/
```

Then point the SDK config at the new bucket (`storageBucket` in
`lib/firebase_options.dart` + the native `google-services.json` /
`GoogleService-Info.plist`) and redeploy `storage.rules`.

> ⚠️ **Do NOT re-run `flutterfire configure` blindly.** It previously mis-wrote the
> bucket name as `the-postbox-game.firebasestorage.app`, which broke report-photo
> uploads. Edit `storageBucket` by hand and verify an upload end-to-end before
> shipping.

## 2. Decommission the us-central1 Cloud Functions

The 8 callables were kept live in us-central1 for old installs. Once Cloud Logging
shows **zero us-central1 invocations for a full release cycle**, delete them:

```bash
firebase functions:delete \
  nearbyPostboxes startScoring updateDisplayName registerFcmToken \
  userClaimHistory submitReport reviewReport routePostboxes \
  --region us-central1
```

The 3 event-driven functions (`onUserCreated`, `onFriendAdded`,
`newDayScoreboard`) were already deleted from us-central1 during the migration to
avoid double-firing — confirm none remain (especially that there is no
us-central1 `newDayScoreboard` Cloud Scheduler job, which would double the
midnight scoreboard rollover):

```bash
gcloud functions list --regions=us-central1
gcloud scheduler jobs list --location=us-central1
```
